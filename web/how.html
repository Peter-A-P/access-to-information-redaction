From a file to a released record

Three stages, and only the last can release anything. The engine proposes; the reviewer's screen records what a person decided; the export applies only those decisions, and refuses until every page has one.

Every offset in the system indexes the same page text, and the reviewer's screen renders that text as characters rather than as a PDF, so the reviewer looks at exactly what the redaction will be applied to.

The rules, in order

The first rule that settles a span decides it, so the order is the design: the requester's own information first, then identifiers that are sensitive whoever holds them, then what is not personal at all, then capacity, then what is public. A span no rule settles is withheld and escalated. This list is checked against the code each time the site is built, and the build fails if they differ.

    {{rule_steps}}

There is no rule that releases something because nothing matched. The last step is always "withhold and ask a person", and Jev is asked only about what reaches it, with its answer accepted only above a confidence threshold, {{model_threshold}}. In a message where an employee writes about their own leave, health or grievance, its release needs {{own_affairs_bar}}.

The reviewer's screen

Server-rendered pages and about a hundred lines of hand-written script, with nothing fetched from anywhere else, so it runs with the network cable out, which is where records like these are usually read. Every action is one form post and one row in the log.

Keyboard first

W withholds, R releases, E escalates, N moves to the next undecided span, so a page can be worked without the mouse.

Select what it missed

Selecting any text offers to withhold it. Detection finds {{recall}} of spans, and a reviewer who could only answer the tool's list would inherit its misses.

Withhold once, withheld everywhere

Withholding a full name, an email address or a number withholds every other exact occurrence in the record, each as its own logged row. Releasing never spreads.

Release the rest

Once the third parties are withheld, the remainder of a page can be released in one action, logged span by span with that reason.

Changes are rows, not edits

A reviewer who changes their mind adds a row; the earlier one stays. The log stores a hash of withheld text, not a second copy of it.

Complete means complete

A page cannot be marked complete while any span on it is undecided, and the refusal names them.

How a number reaches this site

No figure on the overview is typed. Each is read, when the site is built, from a table a measurement command wrote, and the build fails if a figure is missing or no longer reads as it did.

  1. Cast the people firstInvented personas get roles before any document exists: requester, official, third party, public figure, the deceased.
  2. Write the recordsSix kinds of document from templates, rendered to PDF, Word and email, and some degraded into scans. The right answer for every span is known.
  3. Run the tool and score itsever report runs every configuration and scores it against the labels, with intervals resampled over documents.
  4. Write the tablesThe same command writes the results files and splices the tables into the README; nobody edits them.
  5. Build this sitesever site reads those files, runs the demonstration's letter through the engine, and fails on anything it cannot read.

The reviewer study, the scanned track and the published releases follow the same path with their own commands: sever study report, sever eval-scanned and sever eval-releases.

Where this demonstration runs

One container beside project 04's gateway on a small virtual server in Beauharnois, Quebec, behind the same Caddy. Jev's answers for the demonstration's records were recorded once and are replayed from a file, so it calls no model, costs nothing to run and cannot be made to spend money.
