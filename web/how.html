From a file to a released record

Three stages, and only the last can release anything. The engine proposes; the reviewer's screen records what a person decided; the export applies only those decisions, and refuses until every page has one.

Every offset in the system indexes the same page text, and the reviewer's screen renders that text as characters rather than as a PDF, so the reviewer looks at exactly what the redaction will be applied to.

The rules, in order

The first rule that settles a span decides it, so the order is the design: the requester's own information first, then identifiers that are sensitive whoever holds them, then what is not personal at all, then capacity, then what is public. A span no rule settles is withheld and escalated. This list is checked against the code each time the site is built, and the build fails if they differ.

    {{rule_steps}}

There is no rule that releases something because nothing matched. The last step is always "withhold and ask a person", and Jev is asked only about what reaches it, with its answer accepted only above a confidence threshold, {{model_threshold}}. In a message where an employee writes about their own leave, health or grievance, its release needs {{own_affairs_bar}}.

The reviewer's screen

Server-rendered pages and about a hundred lines of hand-written script, with nothing fetched from anywhere else, so it runs with the network cable out, which is where records like these are usually read. Every action is one form post and one row in the log.

Keyboard first

W withholds, R releases, E escalates, N moves to the next undecided span, so a page can be worked without the mouse.

Select what it missed

Selecting any text offers to withhold it. Detection finds {{recall}} of spans, and a reviewer who could only answer the tool's list would inherit its misses.

Withhold once, withheld everywhere

Withholding a full name, an email address or a number withholds every other exact occurrence in the record, each as its own logged row. Releasing never spreads.

Decide what to withhold; the rest is released

The reviewer withholds or escalates what must not go out. Marking the page complete releases everything else, after a confirmation that names anything the tool proposed to withhold, logged span by span with that reason.

Changes are rows, not edits

A reviewer who changes their mind adds a row; the earlier one stays. The log stores a hash of withheld text, not a second copy of it.

Complete means every span decided

Completing a page decides every span still open, as released, and only once the reviewer confirms it. A record cannot be released while any page is incomplete.

How a number reaches this site

No figure on this site is typed. Each is read, when the site is built, from a table a measurement command wrote, and the build fails if a figure is missing or no longer reads as it did.

  1. Cast the people firstInvented personas get roles before any document exists: requester, official, third party, public figure, the deceased.
  2. Write the recordsSix kinds of document from templates, rendered to PDF, Word and email, and some degraded into scans. The right answer for every span is known.
  3. Run the tool and score itsever report runs every configuration and scores it against the labels, with intervals resampled over documents.
  4. Write the tablesThe same command writes the results files and splices the tables into the README; nobody edits them.
  5. Build this sitesever site reads those files, runs the demonstration's letter through the engine, and fails on anything it cannot read.

The reviewer study, the scanned track and the published releases follow the same path with their own commands: sever study report, sever eval-scanned and sever eval-releases.

Where this demonstration runs

One container beside project 04's gateway on a small virtual server in Beauharnois, Quebec, behind the same Caddy. Jev's answers for the demonstration's records were recorded once and are replayed from a file, so it calls no model, costs nothing to run and cannot be made to spend money.

How this was built

I designed this, chose how it is measured and made the judgement calls, from eight years inside a public body that answers access-to-information requests, where the question this tool asks is asked about every page released. I used AI coding assistants (Claude Code) for implementation and drafting, the way a senior engineer uses them in 2026. Every number on this site is reproducible from the repository.

  • Three stages, and only the last can release anything. The engine proposes, a person decides on the reviewer's screen, and the export applies only those decisions, refusing until every page has one.
  • Rules first, then Jev. Deterministic rules in a fixed order, each tied to a provision, settle most spans. Jev decides only what they leave, and below {{model_threshold}} the span is withheld and escalated.
  • No personal information reaches Jev. Every name, contact and identifier is replaced with a placeholder before a request is built, a check refuses any request that still holds a value that was found, and the request goes out only through the portfolio's AI gateway, which logs it as personal data. Jev answers with probabilities, so nothing personal comes back (how).
  • True redaction, tested every time. The text under every box is removed, not covered, and each export is leak-tested on its text layer and on an OCR of the rendered page.
  • A log that cannot be rewritten. Every reviewer action is an append-only, hash-chained row in DuckDB, and the schedule of severances sent to the requester is generated from that log alone.
  • No figure on this site is typed. Each is read from a table a measurement command wrote, and the site's build fails if one is missing or no longer reads as it did.
  • One small container. It runs beside the gateway on a virtual server in Quebec. Jev's answers for the demonstration are replayed from a file, so it calls no model and costs nothing to run.
For the technical reader: the rules the code enforces on itself
  • No path to release without a person. The export asks the session's release gate, which reads the audit log and raises while any page lacks a completion row.
  • Withhold and escalate when unsure. An undecided span is withheld and flagged; no rule releases a span because nothing matched.
  • The audit log is append-only. A reviewer who changes their mind adds a row; each row's hash covers the one before it, and the log stores a hash of the withheld text rather than a second copy of it.
  • Every model call goes through the gateway as personal data, and a test asserts that no raw detected value appears in an outbound request.
  • Every reported number carries an interval and its track, and every table is written by the command that measured it. This site reads those tables, so it cannot disagree with them.
